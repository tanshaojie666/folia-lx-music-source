# Folia 洛雪音源模组

给 [Folia](https://github.com/chthollyphile/folia-major) 加一层**多音源接入**：内置无损直连后端 + 洛雪音乐自定义脚本（LX Music source）宿主。

> **本仓库不含任何音源脚本。** 音源涉及第三方版权与分发授权，请自行获取并导入（见下方「导入音源」）。仓库只提供加载器与直连后端。

---

## ⬇️ [下载最新打包版](https://github.com/tanshaojie666/folia-lx-music-source/releases/latest)

下载 `lx-music-source-*.zip`，解压到 `%APPDATA%\Folia\mods\`，
让目录结构变成 `mods\lx-music-source\main.cjs`，重启 Folia 即可。

包内**只有 `main.cjs` / `client.mjs` / `mod.json` 三个文件**，不含任何音源。
你的音源放在**模组目录之外**的 `%APPDATA%\Folia\lx-music-sources\`（模组首次运行会自动建好）。
放这儿不是随手选的 —— 原因见下方「为什么音源目录在模组目录之外」。

## 它做什么

| 能力 | 说明 |
|---|---|
| 内置无损直连 | 网易云 + 咪咕直连后端，搜索 + 真 FLAC 取链 |
| 洛雪脚本宿主 | 直接加载 LX Music 自定义音源（`.js`），无需装洛雪 |
| 独立开关 | 按 id 单独启用 / 停用任一音源（内置音源也能停用） |
| 随时添加 | 本地 `.js` 路径 或 `http(s)` 链接，一条命令导入 |
| 真无损判定 | 读文件头魔数（`fLaC` / `ID3` / `OggS` / `RIFF`），不看 URL 后缀 |
| 跨平台回退 | 主后端取不到就换其他后端重搜，保证「能播」优先 |
| 崩溃隔离 | 坏脚本的浮空 promise 被进程级护栏拦住，不会带走整个 Folia |

### ⚠️ 一个必须说清的设计事实

Folia 宿主模型是 **同一时刻只有一个在线音乐平台**（`omni.providers` 注册进
`getProviderSummaries()` 那张表，与内置 `netease` 并列）。因此本模组：

- ✅ 每个音源 = **首页「在线音乐平台」里的一个可切换平台**
- ❌ **不是**「搜索时自动问所有音源、结果合并」的多源聚合

日常使用：首页 → 在线音乐平台 → 选一个（建议「网易云（聚合）」）。
**跨平台回退发生在取链阶段、自动进行**，不需要手动切平台。

宿主侧桥接代码（`app.asar` 内）：

```js
const g = e => `folium.${e.replace(':','.')}`;
x = m('omni.providers', {
  validate: ...,
  onAdd:    e => l(b(e.def.providerId, e.def.def)),   // 进同一个注册表
  onRemove: e => c(e.def.providerId),
})
```

## 实测数据

25 首跨语言/跨年代测试曲（周杰伦、陈奕迅、米津玄師、YOASOBI、Queen、Eagles、赵雷、刀郎…）：

```
可播放 25/25   真无损 24/25   失败 0
无损率 96.0%   可播放率 100.0%
取链延迟 163–379 ms（中位数 ~200 ms），有损那一例 7.3 s
```

「真无损」由 FLAC 魔数 + `STREAMINFO`（采样率 / 位深 / 声道）逐字节验证，不是看扩展名。实测样本含 44100Hz/16bit、44100Hz/24bit、48000Hz/16bit、48000Hz/24bit、88200Hz/24bit。

平台分布：**16 首走网易云直连，9 首走咪咕直连**（网易云无资源时自动回退）。

> 唯一一例有损是「晴天 (Live)」——各平台该条目均无无损资源，回退到咪咕 mp3（9 MB）。
> **能播**，但不是无损。这一例也解释了为什么耗时是 7.3 秒：它把全部后端的候选都试完了。

## 安装

1. 把 `main.cjs`、`client.mjs`、`mod.json` 三个文件放进 Folia 模组目录（**不要**在里面建 `sources/`）：

   ```
   Windows: %APPDATA%\Folia\mods\lx-music-source\
   macOS:   ~/Library/Application Support/Folia/mods/lx-music-source/
   Linux:   ~/.config/Folia/mods/lx-music-source/
   ```

   或把整个模组打成 `.zip` 拖进 Folia 的「模组」面板。

2. **设置 → 模组 → 模组系统** 打开总闸（关闭时不会加载任何模组代码）。

3. **设置 → 模组** 里找到「洛雪音源」→ 点 **「仍要启用」** 确认。

   > 该确认**只对当前文件内容生效**；改动 `main.cjs` / `client.mjs` 后需重新确认。
   > 加了音源**不需要**重新确认 —— 音源不在模组目录里，碰不到那个哈希（见下文）。

4. 重启 Folia（或重载模组）。

## 导入音源

**本仓库不提供音源文件。** 三种导入方式，任选：

**方式一 · 命令面板**（`Ctrl+K`，支持拼音/汉字/英文）

```
添加音源  <本地 .js 绝对路径>   或   <http(s) 链接>
```

例：

```
添加音源 C:\Users\me\Downloads\我的音源.js
添加音源 https://example.com/source.js
```

**方式二 · 直接放文件**

把 `.js` 放进**音源目录**，然后执行命令 `重载音源`：

```
Windows: %APPDATA%\Folia\lx-music-sources\
macOS:   ~/Library/Application Support/Folia/lx-music-sources/
Linux:   ~/.config/Folia/lx-music-sources/
```

> 这个目录在**模组目录的外面一层**，不是 `mods\lx-music-source\sources\`。
> 如果你从老版本升上来，原来放在模组里的 `.js` 会自动搬到这里。

**方式三 · 拖 zip**

模组面板支持把 `.zip` 直接拖进去安装。

> 脚本必须符合洛雪音乐自定义音源规范（导出 `lx.send('inited', { sources })`，实现 `musicUrl` / `musicSearch` 等 action）。把洛雪能用的脚本直接拿过来即可。

> **注意**：设置里的「音源设置」区只放**音质 / 跨平台回退 / 启用清单**三项。
> 添加和移除音源**只能走命令面板**（或直接往音源目录丢文件）。

## 命令

`Ctrl+K` 打开命令面板，支持 **拼音 / 汉字 / 英文** 输入。

| 命令 | 拼音 | 作用 |
|---|---|---|
| `音源状态` | `yinyuanzhuangtai` | 列出所有音源及加载状态 |
| `添加音源` | `tianjiayinyuan` | 从路径或 URL 导入 |
| `移除音源` | `yichuyinyuan` | 删除脚本音源（内置音源不能删，只能停用） |
| `启用音源` / `停用音源` | `qiyongyinyuan` / `tingyongyinyuan` | 按 id 单独开关某个音源 |
| `重载音源` | `zhongzaiyinyuan` | 重新扫描音源目录 |

## 设置

设置 → 音源设置：

- **音质**：`无损 24bit` / `无损`（默认）/ `较高 320k` / `标准 128k`
- **跨平台回退**：主后端拿不到时是否换其他后端重搜（默认开）
- **启用清单**：**逗号分隔的音源 id 文本**。留空 = 全部启用；填了就只启用列出的那些

> 「启用清单」与「启用/停用音源」命令是两套机制：清单一旦填值，
> 命令里单独启用的音源也会被清单挡掉。日常只用命令开关，清单留空。

## 设计说明

### 为什么需要这层加载器

Folia 的 Omni 层没有原生的洛雪脚本插槽（上游 issue #155 已关闭为 not_planned，#638 仍开放）。所以这里做了一层适配：把洛雪脚本跑在 Node `vm` 沙箱里，补齐 `lx.request` / `lx.utils.crypto` / `lx.utils.buffer` / `lx.on` 等 API，再把 `musicUrl` / `musicSearch` / `lyric` 映射成 Folia 的 omni provider 接口。

### 为什么内置直连后端

洛雪脚本内部有慢速重试（实测 **6–32 秒**），而内置直连链 **150–300 毫秒**。对网易云来源的歌先走直连，拿不到无损才交给脚本 —— 实测把 32 秒压到 156 毫秒。

### 取链策略

```
1. 直连后端取链（快）
   ├─ 拿到无损 → 直接返回
   └─ 没拿到 / 只有有损 → 让其他直连后端也试同一个 id
2. 仍不满足 → 跨平台回退
   ├─ 用歌名+歌手在全部后端重搜（每后端取前 8 条候选）
   ├─ 两阶段判定：先全量收集，优先返回无损
   └─ 全无无损 → 返回第一个可用结果（能播优先于无损）
3. 质量探测不看后缀，读文件头魔数
```

**为什么回退要试 8 条候选**：同一首歌常有多条搜索结果，排第一的那条可能没有资源。实测多首歌的排首位结果取链为空，往后翻才拿到真 FLAC。

**为什么两阶段而不是边搜边返回**：酷狗常排在网易云前面，它给出 9MB mp3 时若直接收工，就会漏掉网易云同一首歌的 20MB 真 FLAC。

**实测代价**：真正无解的曲目（如「晴天 (Live)」）会把所有后端的所有候选试完，耗时约 7 秒。这是「能播优先」策略的固有成本，正常曲目不受影响（150–380 ms）。

### 为什么音源目录在模组目录之外

这是宿主模组信任模型的硬约束，不是随手选的路径。

Folia 把「启用这个模组」的授权**绑定到模组目录整棵树的哈希**
（`electron/modSystem/modDigest.cjs` 的 `computeModDigest` 会遍历每个文件，
路径和内容都进 sha256）。而 `modSystem.cjs` 的 `resolveTrust` 是这么判的：

```js
if (!digest || stored.digest !== digest) {
  writeTrust(modId, false, null);
  return { enabled: false, trustStale: true };   // ← 整个模组停用
}
```

所以只要音源文件落在模组目录里，**用户每加一个音源，整个模组就被停用一次**，
得重新点一次「仍要启用」。实测（往模组内加一个 `.js`）：

```
3 个文件  sha256:1b6215f8…      ← 干净
4 个文件  sha256:d3d5959a…      ← 加了个音源，哈希变了 → 模组失效
```

放到模组目录**外面**就躲开了这个哈希。同一个操作实测：

```
加 2 个音源  sha256:f2ec56a7…   ← 不变
删 1 个音源  sha256:f2ec56a7…   ← 不变
二次运行     sha256:f2ec56a7…   ← 不变
```

顺带解决第二件事：有版权的音源不会混进发布包。

从 v2.0.1 及更早版本升级时，模组目录里原有的 `sources/` 会被**自动搬到外面并删除**
（只搬 `.js`，同名不覆盖）。那一次哈希会变 —— 但升级本身就改了 `main.cjs`，
你无论如何都要重新确认一次，所以这次变化是免费的。

### 崩溃隔离

洛雪脚本里的浮空 promise 在网络不通时会产生 `unhandledRejection`，逃出 `vm` 沙箱后按 Node 默认行为终止进程 —— 一个坏脚本能崩掉整个 Folia。已加进程级护栏，只隔离来自音源脚本的拒绝。

## 已知限制

- **网易云对部分版权曲目做搜索抑制**。周杰伦原唱在搜索结果里被替换成翻唱/remix（如「晴天(深情版) - Lucky小爱」）。这些是**真 FLAC、能播**，但不是原唱母带。原唱数字 ID 仍可直接解析。
- **聚合站的 `server=netease` 搜索分支已失效**（2026-10-16 实测返回空数组 `[]`），
  但它的 `type=url&br=740` **取链仍然完好**。因此 v2.0.2 起「网易云（聚合）」的搜索
  改走**网易云官方接口**（`cloudsearch/pc`），聚合站降为备路，再兜底到 migu 搜索。
  官方搜索给的原唱 id 交给聚合站取链，实测 12/12 全拿到真 FLAC —— 顺带让周杰伦的
  版权曲也能取到**原唱**无损，不再只能拿翻唱。
- **第三方洛雪音源大多已失效**。实测多个公开聚合音源的后端域名已不可达，返回 `fetch failed` / `unknown error`。脚本能否用取决于其自身后端是否存活 —— 这是音源的问题，不是加载器的问题。
- **酷我 / 咪咕 / 酷狗的 web 搜索接口不可用**（400 / 返回 HTML / 连接失败），因此未作为独立搜索源注册。咪咕保留了**取链**能力，实测 9 首真无损由它提供。
- 直连后端实际生效两个：**网易云**（主）与**咪咕**（回退）。
